# Step 1: Precomputed Basin Resource Matrix (v8, 2026-06-01 scope)

Generated by `notebooks/step1_precompute_resource_matrix.ipynb` or
`code/run_step1_precompute.py --workers N`.

The basin × period resource matrix is the geological foundation of all of
Step 2 screening. For every study basin in `input/basin_data/Global.xlsx` and
every storage period in [10, 20, …, 150] years, CO₂BLOCK computes the maximum
sustainable annual injection rate (`Region_Q_Mt_yr`) and the optimal well
configuration (`Number_of_Wells`, `Distance_km`).

## Active V8 scope

The active study pool is 10 regions: Australia, Brazil, Canada, China,
EU, Indonesia, Middle East, Thailand, UK, and US. EU is defined as Europe
without UK for basin assignment and is reported as `EU` in outputs and figures.
The resulting matrix contains 123 basins and 1 845 basin-period rows.

## Run parameters

| Parameter | Value | Description |
|-----------|------:|-------------|
| `INJ_DURATION_YR` | 150 | Maximum injection duration, 15 periods [10, …, 150 yr] |
| `STORAGE_PERIOD_STEP_YR` | 10 | Period increment |
| `nr_dist` | 100 | Well-spacing search scenarios per basin |
| `maxQ` | 20 Mt/yr | Maximum sustainable rate per well (technical) |
| `minQ` | 1 Mt/yr | Minimum site rate; single-well sites exempt |
| `dist_min` | 2 km | Minimum inter-well distance |
| `nr_well_max` | auto | floor(area / dist_min²) |
| `rw` | 0.2 m | Well radius |
| `correction` | off | Pressure-superposition error correction |

## Output files

### `precompute/basin_period_resource_long.csv` (1 845 rows)

Long-format matrix, one row per (basin, period). 123 basins × 15 periods.

| Column | Type | Description |
|--------|------|-------------|
| `Region_no` | int | Basin ID (row order in `Global.xlsx`, 1–203) |
| `Region_name` | str | Basin name |
| `Period_yr` | int | Storage period in years (10, 20, …, 150) |
| `Region_Q_Mt_yr` | float | Maximum feasible injection rate (Mt/yr) at this period |
| `Number_of_Wells` | int | Optimal well count for the selected configuration |
| `Max_Capacity_Gt` | float | `Region_Q_Mt_yr × Period_yr / 1000` |
| `Max_Q_Mt_yr` | float | Maximum rate across all well configurations (pre-`minQ` filter) |
| `Optimum_Q_Mt_yr` | float | Optimal per-well rate of the selected configuration |
| `Distance_km` | float | Optimal inter-well spacing (km) |
| `AssignedCountry` | str | **Raw majority country** of the basin (e.g. USA, France, Saudi Arabia) |
| `RegionGroup` | str | Raw region from `Global.xlsx` (e.g. Europe, Middle East) |
| `ScreeningCase` | str | **v8 study region** the basin rolls up to (US, …, EU, Middle East, Brazil) |

`AssignedCountry`/`RegionGroup` are the raw geological labels; Step 2 maps them to
study regions with `resolve_region_nos` (e.g. `EU` = `RegionGroup == Europe` and
`AssignedCountry != UK`; `Middle East` = `RegionGroup == Middle East`; `Brazil` =
`AssignedCountry == Brazil`). `ScreeningCase` is that same study label
precomputed for convenience and for the figures.

The annual rate decreases as storage period lengthens because pressure
accumulates over time, limiting sustainable injection.

## How to regenerate

```bash
cd 02_co2block_screening/code
python run_step1_precompute.py --workers 4      # full v8 matrix (all 123 basins)
# or, after a prior run, add only new regions incrementally:
# python build_step1_v8_incremental.py
# or, equivalently, the notebook:
# jupyter nbconvert --execute notebooks/step1_precompute_resource_matrix.ipynb
```

Step 1 outputs are inputs to Step 2; **changing them invalidates all Step 2
outputs**.
